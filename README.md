# 3D segmentation of honeybee mushroom-body microglomeruli and synapsin-positive units

This repository contains MATLAB scripts for 3D segmentation and morphometric analysis of synaptic structures in the honey bee mushroom body (MB), accompanying the following publication:

Cabirol, A.; Paoli, M.; Fehrmann, A., Calliari, N.; Fayolle, M.; Bariselli, S.; Schloetel, J.-G.; Haase, A. 
Neural correlates for neonicotinoid-induced impairment of olfactory long-term memory. bioRxiv 2026, 2022.05.04.489639. https://www.biorxiv.org/content/10.1101/2022.05.04.489639

The code was developed for two related imaging workflows:

1. **Two-photon imaging** — segmentation and characterization of **microglomeruli (MGs)** within a manually defined mushroom-body lip region.
2. **STED imaging** — segmentation and characterization of **MGs**, followed by segmentation of smaller **synapsin-positive units (SPUs)** within each MG. SPUs are the size of individual synapses.

The scripts use repeated intensity thresholding together with 3D connected-component analysis to identify structures that persist across thresholds. Objects are filtered by size and merged/rejected according to spatial-overlap criteria before morphometric quantities are calculated.

> **Important:** the scripts currently contain experiment-specific absolute paths, file-name conventions, voxel sizes, and segmentation parameters. These must be adapted to the local data organization before running the code.

All helper functions used by a workflow are currently defined as local functions at the end of the corresponding MATLAB script.

### `MG_segmentation_and_mask_generation_twophoton.m`

Segments MGs in 3D two-photon image stacks inside a supplied mushroom-body lip mask.

Main operations:

- loads the raw 3D two-photon stack and corresponding lip mask;
- restricts the image to the masked MB lip volume;
- performs repeated thresholding over a user-defined intensity range;
- extracts 3D connected components and their geometrical properties;
- identifies objects that correspond to the same MG across thresholds;
- calculates MG volume, aspect ratio, centroid-to-centroid distances, and total lip volume;
- optionally generates a colour-coded segmentation overlay;
- combines results obtained by parallel workers into summary CSV files.

### `Drift_correction_STED_data2024.m`

Performs XY drift correction of STED image stacks from the 2024 dataset using drift estimates obtained with the **Correct 3D Drift** plugin in Fiji (ImageJ).

Main operations:

- loads the original STED image stacks and the corresponding Fiji-generated `shifts.txt` files;
- applies the estimated XY shifts to each frame using integer pixel coordinates without interpolation;
- fills newly exposed image regions with a constant background intensity of 128;
- saves the drift-corrected image stacks as multipage TIFF files (`drift_corrected_background_<original_filename>`);
- writes a CSV file containing the final-frame X and Y shift values (total cumulative drifts) for each processed image.

The drift-corrected TIFF stacks are subsequently used as input for the 2024 STED MG-segmentation workflow.

### `MG_segmentation_and_mask_generation_STED.m`

Segments MGs in 3D STED image stacks and creates one MG-restricted image stack for every detected MG. These MG stacks are subsequently used as the input for SPU segmentation.

Main operations:

- loads a STED z-stack (original data for the older dataset or drift-corrected data for the 2024 dataset);
- resamples the stack to a more isotropic grid;
- normalizes and filters the data;
- performs repeated thresholding and 3D connected-component analysis;
- identifies corresponding MG detections across thresholds;
- calculates MG volume, aspect ratio, and pairwise MG distances;
- creates a separate TIFF stack for every segmented MG;
- combines results obtained by parallel workers into summary CSV files.

The script contains alternative code sections for the **older STED dataset** and the **2024 STED dataset**. At present, switching between these formats is done manually by activating/deactivating the corresponding blocks marked `STED old` and `STED 2024`.

### `SPU_segmentation_twophoton_criterium.m`

Segments SPUs inside the MG-restricted STED stacks generated by `MG_segmentation_and_mask_generation_STED.m`.

Despite the filename, this script operates on **STED MG masks/stacks**. The term `twophoton_criterium` refers to the region-selection criterion used in the segmentation logic, not to the imaging modality of its input data.

Main operations:

- reads each MG-restricted TIFF stack (`Mask_*_d.tif`);
- matches it to the corresponding original STED image;
- determines the effective physical voxel size after the resampling performed during MG segmentation;
- performs repeated thresholding within each MG;
- identifies SPUs that persist across thresholds;
- calculates the number of SPUs per MG;
- calculates the mean SPU volume and mean SPU aspect ratio for each MG;
- writes one CSV file per sample/brain and measured property.

# Workflow

The two imaging modalities follow slightly different pipelines.

## Two-photon workflow

```text
Raw 2P z-stack
      +
MB lip mask
      │
      ▼
MG_segmentation_and_mask_generation_twophoton.m
      │
      ├── MG volumes
      ├── MG aspect ratios
      ├── pairwise MG distances
      ├── MB lip volume
      └── optional colour-coded segmentation TIFF
```

## STED workflow

```text
Raw STED z-stack
      │
      ├── Older STED ──────────────────────────┐
      │                                        │
      └── STED 2024                            │
              │                                │
              ▼                                │
      Fiji: Correct 3D Drift (shifts.txt)      │
              +                                │
      Drift_correction_STED_data2024.m         │
              │                                │
              ▼                                │
      Drift-corrected TIFF ────────────────────┘
                         │
                         ▼
MG_segmentation_and_mask_generation_STED.m
      │
      ├── MG morphometry
      └── one MG-restricted TIFF stack per MG
                         │
                         ▼
           SPU_segmentation_twophoton_criterium.m
                         │
                         ├── SPU count per MG
                         ├── mean SPU volume per MG
                         └── mean SPU aspect ratio per MG
```

The SPU analysis depends on the output of the STED MG-segmentation step.

# Requirements

The scripts are written for MATLAB and use functions from several MATLAB toolboxes.

At minimum, the current implementation requires:

- **MATLAB**
- **Image Processing Toolbox**
- **Parallel Computing Toolbox**
- **Statistics and Machine Learning Toolbox**
- **Fiji (ImageJ)** with the **Correct 3D Drift** plugin (for STED 2024 drift correction)

The code reads and writes multi-page TIFF stacks using MATLAB's `Tiff` interface.

The scripts were designed for execution on a system where several MATLAB workers are available. See the notes on parallel processing below.

# Input data

## 1. Two-photon MG segmentation

The two-photon script expects a raw 3D image stack and a corresponding binary/ROI mask defining the mushroom-body lip.

The default directory organization is:

```text
<datpath>/
├── Tiff images/
│   ├── A1_image.tif
│   ├── A2_image.tif
│   └── ...
└── LipMask/
    ├── A1_LipMask.tif
    ├── A2_LipMask.tif
    └── ...
```

For a sample identifier such as `A1`, the required pair is therefore:

```text
Tiff images/A1_image.tif
LipMask/A1_LipMask.tif
```

Both files must be multi-page TIFF stacks with matching spatial dimensions and number of z-slices.

### Selecting files

Set:

```matlab
analyze_all_images = 1;
```

to process all files matching:

```text
Tiff images/*_image.tif
```

or set:

```matlab
analyze_all_images = 0;
filevector = {'A1', 'A2'};
```

to analyze selected samples.

---

## 2. STED 2024 drift correction

The drift-correction script `Drift_correction_STED_data2024.m` expects an original STED image stack and a corresponding `shifts.txt` file generated using the **Correct 3D Drift** plugin in Fiji (ImageJ).

The expected directory organization is approximately:

```text
STED_data2024_new_shift/
└── <sample_id>_external/ or <sample_id>_internal/
    └── Sample*/
        ├── *STAR RED STED*
        └── shifts.txt
```

The drift-corrected TIFF stack is saved in the same `Sample*` directory.

## 3. STED MG segmentation

The STED script expects multi-page TIFF/OME-TIFF z-stacks containing the synapsin signal.

Two dataset organizations are represented in the current script.

### Older STED dataset

The active code searches for:

```text
<folderpath>/STED/Sted data/*.tif
```

and derives the sample identifier from the filename.

### STED 2024 dataset

For the 2024 dataset, the STED script uses the drift-corrected TIFF stacks generated by the drift correction script as input.

Alternative code is included for a nested structure of approximately the form:

```text
STED_data2024_new_shift/
└── <sample_id>/
    └── Sample*/
        └── drift_corrected_background_*STAR RED STED*.tif[f]
```

The relevant `STED 2024` blocks in `MG_segmentation_and_mask_generation_STED.m` must currently be enabled manually.

The 2024 branch also contains optional code for selecting images based on the drift table containing cumulative XY drift values.

## 4. SPU segmentation

The SPU script requires **both**:

1. the MG-restricted TIFF stacks generated by the STED MG script; and
2. the corresponding original STED image stacks.

The expected MG-mask organization is:

```text
OTSU_MASKS_<trial_name>/
├── <sample_1>_XY-OTSU/
│   ├── Mask_1_d.tif
│   ├── Mask_2_d.tif
│   ├── Mask_3_d.tif
│   └── ...
├── <sample_2>_XY-OTSU/
│   └── ...
└── ...
```

Each `Mask_<n>_d.tif` contains the image intensity inside one segmented MG and zeros outside that MG; it is therefore an **MG-restricted image stack**, rather than only a binary label image.

The script matches each `<sample>_XY-OTSU` directory to its original STED image using the sample identifier. The raw image dimensions are needed to reconstruct the physical voxel dimensions after interpolation/resampling.

# Parameters that must be checked before analysis

All scripts begin with experiment-specific configuration sections. These should be reviewed for every dataset.

## Common segmentation parameters

| Parameter | Meaning |
|---|---|
| `trial_name` | Name used to identify the analysis and output directories. |
| `minl` | Lowest normalized/intensity threshold tested. |
| `maxl` | Highest normalized/intensity threshold tested. |
| `th` | Number of thresholds sampled between `minl` and `maxl`. |
| `d2` | Spatial distance criterion used when deciding whether detections at different thresholds belong to the same structure. |
| `volmin` | Minimum accepted object volume, expressed in the units used by the corresponding script. |
| `volmax` | Maximum accepted object volume. |
| `x_size`, `y_size`, `z_size` | Original voxel dimensions in micrometres. |

Additional script-specific parameters include:

- `ol` in the STED MG script: required number of overlapping detections used in the MG-selection criterion;
- `compression_factor` in the SPU script: optional 3D image scaling factor before SPU segmentation;
- `pixelsize`: lateral pixel size used by several distance/volume conversions.

The scripts save the parameter values used for each run to a `parameters.csv` file in the corresponding results directory.

# Segmentation strategy

Although the exact overlap criterion differs slightly between the STED MG workflow and the other two segmentation scripts, the general approach is the same.

## 1. Repeated thresholding

Instead of applying a single fixed threshold, each volume is segmented at `th` intensity levels between `minl` and `maxl`.

For each threshold:

1. the image is binarized;
2. connected 3D regions are identified with `regionprops3`;
3. centroid, volume, voxel indices, and principal-axis lengths are extracted;
4. regions outside the allowed volume range are removed.

## 2. Linking detections across thresholds

The same biological structure can appear at several intensity thresholds. The scripts therefore compare detections across thresholds using centroid distance and voxel overlap/containment.

Smaller or redundant detections are removed, and a representative region is retained for subsequent morphometry.

## 3. Morphometry

Depending on the workflow, the scripts calculate:

- object volume;
- principal-axis lengths;
- aspect ratio (`largest principal axis / smallest principal axis`);
- centroid positions;
- pairwise centroid distances;
- object counts.

All physical dimensions are converted to micrometres or cubic micrometres using the voxel dimensions defined in the script and, for STED data, the resampling factors introduced during preprocessing.

# Output

## Two-photon MG segmentation

The results are written below:

```text
Results_2P_MG_<trial_name>/
```

The active analysis produces:

- `parameters.csv` — segmentation and voxel-size parameters;
- `Results_vol_<first>-<last>_<trial_name>_final.csv` — MG volumes in µm³;
- `Results_aspectratio_<first>-<last>_<trial_name>_final.csv` — MG aspect ratios;
- `Results_dist_<first>-<last>_<trial_name>_final.csv` — pairwise MG centroid distances in µm;
- `Results_lipvol_<first>-<last>_<trial_name>_final.csv` — volume of the analyzed MB lip ROI in µm³;
- worker-level intermediate CSV files created during parallel processing;
- optionally, colour-coded TIFF overlays under `Coloured_regions/`.

The script also defines an axes-summary output (`Results_axes_...`), but the corresponding code that writes the per-object principal-axis values is currently commented out.

> **Note:** some worker-level output filenames in this script still contain the string `STED_Mask`. This is a naming artefact in the current code; the data are generated from the two-photon workflow.

---

## STED 2024 drift correction

The drift-corrected image stacks are saved in the same directories as the original STED images:

```text id="c6n6qd"
drift_corrected_background_<original_filename>
```

The script also generates a CSV file containing the total cumulative X and Y drift for each processed image.

---

## STED MG segmentation

Numerical MG results are written below:

```text
Results_STED_MASKS_<trial_name>/
```

The active outputs include:

- `parameters.csv`;
- final MG-volume CSV;
- final MG-aspect-ratio CSV;
- final pairwise-MG-distance CSV;
- worker-level intermediate CSV files.

As in the two-photon script, code for exporting principal-axis values exists but is currently commented out.

### MG-restricted image stacks

The MG stacks required for the SPU analysis are written below:

```text
OTSU_MASKS_<trial_name>/
└── <sample>_XY-OTSU/
    ├── Mask_1_d.tif
    ├── Mask_2_d.tif
    └── ...
```

Each TIFF contains the filtered STED intensity image restricted to one segmented MG.

---

## SPU segmentation

SPU results are written below:

```text
SPU_Count/<trial_name>/
├── parameters.csv
├── VOLUME/
├── COUNT/
├── ASPECT RATIO/
├── AXES/
└── Coloured_regions/
```

The currently active outputs are one CSV file per sample/brain and property:

### `COUNT/`

```text
Results_STED_SPU_count_<sample>.csv
```

Contains the **number of segmented SPUs in each MG**. Row `n` corresponds to `Mask_n_d.tif`.

### `VOLUME/`

```text
Results_STED_SPU_vol_<sample>.csv
```

Contains the **mean SPU volume (µm³) within each MG**.

### `ASPECT RATIO/`

```text
Results_STED_SPU_ratio_<sample>.csv
```

Contains the **mean SPU aspect ratio within each MG**.

The `AXES/` directory is created, but writing of SPU principal-axis output is currently commented out.

The present version deliberately retains separate per-sample result tables; the comments in the script indicate that concatenation across brains/samples is performed subsequently in a separate analysis step.

# Running the analysis

## Two-photon MG analysis

1. Place the raw z-stacks in `Tiff images/`.
2. Place the corresponding lip masks in `LipMask/`.
3. Edit the path section of `MG_segmentation_and_mask_generation_twophoton.m`.
4. Check the voxel dimensions and segmentation parameters.
5. Select the images with `analyze_all_images` or `filevector`.
6. Start the required MATLAB parallel pool.
7. Run:

```matlab
MG_segmentation_and_mask_generation_twophoton
```

## STED 2024 drift correction

For the 2024 STED dataset, XY drift correction is performed before MG segmentation.

1. Estimate the XY drift using the **Correct 3D Drift** plugin in Fiji (ImageJ).
2. Save the resulting `shifts.txt` file in the same `Sample*` directory as the corresponding original STED image stack.
3. Edit `folderpath` and `resultsfolder` in `Drift_correction_STED_data2024.m`.
4. Select the images to analyze using `analyze_all_images` or `filevector`.
5. Run:

```matlab
Drift_correction_STED_data2024
```

The script saves drift-corrected TIFF stacks (`drift_corrected_background_<original_filename>`) alongside the original images and writes a CSV file containing the total cumulative X and Y drift for each processed image.

The drift-corrected TIFF stacks are subsequently used for STED MG segmentation.

## STED MG analysis

1. Edit the path section of `MG_segmentation_and_mask_generation_STED.m`.
2. Activate the appropriate `STED old` or `STED 2024` code blocks.
3. Check voxel sizes, preprocessing parameters, and MG segmentation parameters.
4. Select the images to analyze.
5. Start the required MATLAB parallel pool.
6. Run:

```matlab
MG_segmentation_and_mask_generation_STED
```

This generates both MG morphometry and the `OTSU_MASKS_<trial_name>` directory required for the next step.

## SPU analysis

1. Set `trial_name` to the MG-mask analysis that should be used.
2. Set `datpath` to the corresponding `OTSU_MASKS_<trial_name>` directory.
3. Set `rawdata_path` so that the corresponding original STED images can be found.
4. Check the original voxel dimensions and SPU segmentation parameters.
5. Run:

```matlab
SPU_segmentation_twophoton_criterium
```

# Reproducibility notes

For every analysis, record at least:

- MATLAB version;
- toolbox versions;
- Fiji (ImageJ) version and Correct 3D Drift plugin settings, when processing STED 2024 data;
- `trial_name`;
- voxel dimensions;
- threshold range (`minl`, `maxl`);
- number of thresholds (`th`);
- spatial-overlap criterion (`d2` and, for STED MG analysis, `ol`);
- minimum and maximum object volumes;
- `compression_factor`, when used;
- whether the old or 2024 STED input branch was used.

The automatically generated `parameters.csv` files capture most numerical segmentation parameters, but not all choices related to file organization and manually activated code branches.

---

# Current limitations

The present scripts reflect the analysis pipeline used for the original experiments and are not yet packaged as a general-purpose segmentation toolbox. In particular:

- paths are hard-coded and must be edited locally;
- STED dataset versions are selected by commenting/uncommenting code blocks;
- several filename conventions are experiment-specific;
- some legacy variable and output names remain in the scripts;
- principal-axis CSV export is currently disabled in several places;
- parallel execution assumes a particular worker/file organization;
- parameter validation and automatic input consistency checks are limited.

These points do not change the segmentation logic, but should be considered when applying the code to a new dataset.
